## 2. 録画の前の準備

1. **停止 → 拒否 → 再開は、本番で確かめた**（2026-11-07 01:29〜01:31、法律 p0.4.5。[`docs/validation.md`](../validation.md) §4）。この山場は確定。録画の【実操作】は、同じ操作をもう一度行う
2. **T-025・T-026 は統合済み**。T-027（画面の題）の統合の後に録画する
3. **通しのリハーサルを1回**行い、秒数を計る
4. **再開の条件**（[`SPEC.md` §8](../../vgdd/kernel/SPEC.md)、`kernel-resume.sh`）：証拠の検証が通る、`.git/config` が基準値と同じ、main の checkout が main ブランチにあり未コミットの変更と未追跡のファイルがない、停止の時点の main が今の main の祖先、停止の後に main へのコミットがない（あれば `--accept-main`）。引数の理由も要る。書きかけの票と下書きは、止める前に片付ける
5. **裁判所を動かしておく**。画面の状態は裁判所の周回で書き出される。止まっていると画面が「停止中」に変わらない。画面の取得も 60 秒ごとで、帯が出るまでの時間は保証しない。再読み込みするか、待ちを編集で詰め、詰めたことを字幕に出す
6. 拒否を見せる Bash は、無害な1行にする。**拒否の文には停止の理由が出る**ので、理由の文も合成データだけにする
7. 録画の直前に、オーナーが操作の集計 `summary.json` を書き出し直す（今は 11/6 06:49 のままで、Kernel の区画の記録数と食い違う）。**`summary.json` は Git で追跡しているので、書き出した後、止める前にコミットする**（未コミットのままだと再開が拒否され、停止の後にコミットすると `--accept-main` が要る）。状態の `generated_at` も見て、古いまま数字を読まない
