## 0. 録画の前の準備（オーナー）

1. `npm run dev` を起動、`npm run seed -- --reset` で合成データを入れ直す
2. **fixture（録画の前提条件）**：手順書の原案と「AI でも確かめる」の保存済みの出力を `npm run demo:capture -- --extras` で採取して中身を見てコミット（T-020。API キーのある環境）。**採取の後に `seed --reset` から通しで1回リハーサルし、各場面の秒数を計る**。S-4 の原案に要る「承認済み 2 件以上」は seed の新人A・先輩C の 2 件で満たされ、デモで新人A が承認する分は 3 件目になる（原案の fixture は採取時の材料と一致する必要がある。T-draft-fingerprint-no-id の統合前は `seed --reset` の回数に注意）。採れていなければ §2 の代替
3. **本筋は実装済みの画面だけで組む**。Kernel の区画（`/governance` の先頭）は票 `T-draft-kernel-ui` が統合され動作を確かめられた場合だけ差し込む**任意の項目**。字幕の数字（適合性 N/N など）は画面に出た実測値だけを読む
4. ユーザーの切り替えは画面上部のセレクタ。録画は新人A で始める
5. 罠の語は登録語句（架空の顧客名「ホクト製菓」ほか。`src/lib/registered-terms.json`）。実在の名は使わない
6. 画面の遷移は操作の単位で：S-2 の「チームに共有する」→ S-3、S-3 の承認の後は見出しの nav「チームの知恵」→ S-4、新人B はセレクタで切り替え → S-1

## 3. 録画の注意

- 画面は 1280×800 以上、文字は `text-sm` 以上が読める倍率で
- 罠の語・合成データ以外の文字を入力しない（録画に実案件の語を出さない）
- 字幕は画面の下に固定の帯で。ナレーションは字幕と同じ文（審査員が音なしでも分かる）
- `/governance` の数字は録画の時点のものを読み上げない（録画の後も変わるため、「件数はここに」で止める）
- 「半日」「30分」は原体験の話で**実測の数字ではない**。字幕では「〜のころ」「〜だった」の語りの形にし、計測結果のように見せない
- **通しのリハーサルで秒数を計る**。3分に収まらなければ、0:15〜0:30 のつぶやきを1つに、0:30〜0:50 の追加の質問を省く
- 実 API を使う録画なら、S-2 と S-3 の AI の待ち時間（数秒〜十数秒）を見込む。デモモード（fixture）なら待ちはない
