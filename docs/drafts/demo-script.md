## 2. 録画の前の準備

1. **停止 → 拒否 → 再開は、本番で一度確かめた**（2026-11-07 01:29〜01:31、法律 p0.4.5。[`docs/validation.md`](../validation.md) §4）。今の法律 p0.4.8 では通していないので、11/8 06:00 からのリハーサルで一度通す。録画の【実操作】は、同じ操作をもう一度行う
2. **統治シアター（T-028〜T-034）は `/governance` に統合済み**（11/7 20:2x）。試作の入口 `/governance/theater` は映さない。提出記録は凍結の直前に最新にする（今の写しは p0.4.5・02:03 で、判断待ちに T-027 が出る）
3. **通しのリハーサルを1回**行い、秒数を計る
4. **再開の条件**（[`SPEC.md` §8](../../vgdd/kernel/SPEC.md)、`kernel-resume.sh`）：証拠の検証が通る、`.git/config` が基準値と同じ、main の checkout が main ブランチにあり未コミットの変更と未追跡のファイルがない、停止の時点の main が今の main の祖先、停止の後に main へのコミットがない（あれば `--accept-main`）。引数の理由も要る。書きかけの票と下書きは、止める前に片付ける
5. **画面の確認は一時的な作業ツリーで行い、main の checkout で `npm run dev` を動かさない**。「稼働中の観測」に停止を映すには、作業ツリーの `docs/governance/kernel-state.json`・`kernel-invariants.json` を通常のファイルとして置く（記号リンクは読み込み側が拒否する）。停止の後、裁判所が停止中の写しを書き出したことを確かめてから、オーナーが2つのファイルを作業ツリーへコピーする。再開の後も同じ手順で更新する。リハーサルで確かめる
6. **裁判所を動かしておく**（`--hold`）。画面の状態は裁判所の周回で書き出される。止まっていると画面が「停止中」に変わらない。統治シアターは source を切り替えたときに1回だけ取得し、ポーリングしない。写しを更新したら「提出記録」→「稼働中の観測」と切り替える（選んでいる source をもう一度押しても取得しない。ページを再読み込みすると「提出記録」に戻るので、改めて「稼働中の観測」を選ぶ）。待ちは編集で詰め、詰めたことを字幕に出す
7. 拒否を見せる Bash は、無害な1行にする。**拒否の文には停止の理由が出る**ので、理由の文も合成データだけにする
8. 録画の直前に、オーナーが操作の集計 `summary.json` を書き出し直す（今は 11/7 12:27 の生成）。**`summary.json` は Git で追跡しているので、書き出した後、止める前にコミットする**（未コミットのままだと再開が拒否され、停止の後にコミットすると `--accept-main` が要る）。状態の `generated_at` も見て、古いまま数字を読まない
