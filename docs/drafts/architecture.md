## 責務と権限

| 機関 | 実体 | すること | できないこと |
|---|---|---|---|
| 市民（オーナー） | 人 | 仕様の承認、裁定、夜間の合格の統合の承認、停止と再開、法律の制定 | Kernel の外にいる。人の許可は Kernel では止められない |
| 立法 | 立法補佐（Claude）、憲法審査（ツールなし） | 法律と票の起草、改正案の憲法審査 | 効力を与えること。起草しただけでは効かない |
| 行政 | 行政の長と作業員（Claude Code） | 作業員を起こす、worktree で実装する、統合を申請する | main への統合。行政の長が main に直接コミットできるのは `docs/` の下だけ。作業員は自分の worktree の外に書けない |
| 司法 | judge（Claude）、Codex（別系統） | 差分・受け入れ条件・監査の結果だけで判定する | 実装を直すこと。行政の説明を読むこと |
| Kernel | フック、権限ルール、sandbox、裁判所のプロセス、証拠ストア | 決めた規則を強制し、記録する。統合できるのは裁判所と、オーナーが動かす release だけ | 自分で合否を判断すること。第4の権力ではない |

権限の全体は [`capabilities.json`](../vgdd/kernel/capabilities.json) にあり、止める層と確かめる試験が権限ごとに書いてあります。

## 信頼の境界

外側ほど強い権限を持ちます。内側が外側を変えられないように強制します。限界は下の節にあります。

| 境界 | 内側 | 外側 | 境界を作る仕組み |
|---|---|---|---|
| 指示文と実行環境 | エージェントへの指示 | フック・権限ルール・sandbox | 指示文に頼らず、実行の前に判定する。**約束だけのものは権限の表に promise と書いて公開する** |
| worktree | 作業員 | main の checkout | isolation とフック |
| sandbox | 行政のプロセス | 裁判所・Z3 | OS の sandbox と別プロセス。裁判所はオーナーの権限で sandbox の外で動く |
| 司法の入力 | 司法 | 行政の説明・会話 | 裁判所が入力を機械的に集める。司法はツールを持たない |
| 同じ機械 | Kernel 全体 | 管理者権限（オーナー） | **境界なし。** オーナーは Kernel と記録を変えられる。強い保証には外部の信頼基盤が要る |

エージェントが読める状態の表示用ファイル（`docs/governance/`）は表示にだけ使い、Kernel の判断には使いません。

## 1枚の票の流れ

1. 立法か行政が票を起草する
2. オーナーが承認し、仕様の指紋が Z3 に残る
3. 行政の長が作業員を起こし、作業員が worktree で実装する
4. 行政の長が差分を確かめて申請する
5. 裁判所が監査と2系統の司法を動かす
6. 合格なら裁判所が統合する。夜間は統合せずに held（統合の承認待ち）にし、オーナーが画面を見てから release（統合の実行）する

状態の意味と次の担当は [`validation.md` §3](validation.md) にあります。
