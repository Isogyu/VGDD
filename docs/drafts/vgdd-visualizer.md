# VGDD の可視化（作品）の要件と画面の構成（下書き。2026-11-06 22:5x、立法補佐。D-64）

位置づけ：**下書き**。オーナーの確認の後、画面ごとに票（T-025〜）にする。作品の主役は VGDD Governance Kernel とその可視化。見せるのは作り物の例ではなく、つぶやき業務ログを作ったときの**本物の運用の記録**（票 25 枚、判定 115 件、不一致 13 件、裁定 2 件、法律の版 p0.2〜p0.4.4）。

## 1. 伝えたいこと（3分のデモで）

1. AI のチームが、憲法と法律のもとで、役割を分けて動いている（立法・行政・司法・Kernel・市民）
2. Kernel が、AI の善意やプロンプトではなく、実行時に強制している（停止すると全員が止まる）
3. 法律は、AI 自身が見つけた穴を判例にして育ってきた（p0.4.3 の G15・G19 など）
4. 不変条件 INV-01〜12 を、どこまで判例で確かめているかを正直に見せる（強制・一部・対象外）

## 3. 優先順位（凍結 11/8 09:00 まで）

1. **V3 法律の歴史**：いちばん語れる場面。データは立法補佐が書き、画面は作業員（票1枚）
2. **V1 全体図 ＋ V2 停止の全面表示**：デモの冒頭と山場。今あるデータだけで作れる（票1枚）
3. **V4 票の運命**：§6 の時刻だけで作る形なら票1枚。裁判所の出来事まで出すなら法律の改正が先
4. 本番の停止の実演（K2）を記録し、デモで V2 を見せる

## 4. 守ること

- 写しに出すのは公開してよい集計だけ（パス・ハッシュ・理由の本文・セッション ID を出さない。法律 p0.4.3〜p0.4.4 のまま）
- 画面は写しを**表示にだけ**使う（判断の根拠にしない）
- 「実装済み」と書くのは、判例か実運用の記録で確かめたものだけ（憲法の約束4）
- つぶやき業務ログの画面は残す（題材）。新しい機能は足さない（約束3）
