# Windows（WSL2）での検証の手順書と結果の様式（下書き）

> **下書き**（2026-11-07 23:4x、立法補佐）。オーナーの判断（D-66 の後、11/7 23:2x）：今回の検証は WSL2 を第一候補にし、ネイティブ Windows は別の到達点とする。**WSL2 で macOS の保護（`sandbox-exec`）をそのまま代わりにできるとは考えない**。保護の境界が成り立たなければ、実稼働（AI に作業させること）を始めずに報告する。
>
> この手順は**合成データだけ**で行う。秘密（API キー・トークン・パスワード）、実在の個人情報、生のログを、結果の報告に貼らない。

## 0. 段階と、今回「確かめた」と書いてよい範囲

| 段階 | 中身 | AI を動かすか |
|---|---|---|
| ① 閲覧と起動 | clone して画面を開く。提出記録が出る | 動かさない |
| ② 適合性テスト | `node vgdd/conformance/run.mjs` | 動かさない |
| ③ 保護の境界 | Claude Code の sandbox が WSL2 で動き、作業フォルダの外の Z3 を読めない・書けないか | 動かさない（`claude` の sandbox の設定の確かめだけ） |
| ④ 小さな票 | 合成の小さな票を承認し、作業員 → 司法 → 統合まで通す | **③が成り立ったときだけ** |
| ⑤ 負例 | 未承認・禁止の操作・停止・再開・予算の上限・再試行の上限 | ③④の後 |

通った段階だけを「確かめた」と書く。①②だけ通れば「WSL2 で閲覧と適合性テストを確かめた。保護の境界と実稼働は未検証」と書く。

| 項目 | 内容 | 目安 |
|---|---|---|
| WSL2 と Ubuntu | `wsl --install -d Ubuntu`（管理者の PowerShell。再起動が要ることがある） | 15〜30 分 |
| Node.js 24 以上、git、jq | Ubuntu の中で入れる | 10 分 |
| リポジトリ | リポジトリが非公開のうちは、clone にオーナーの GitHub の認証が要る（トークンは報告に書かない）。Ubuntu のホームの下（`~/`）に clone する。**`/mnt/c/` の下に置かない**（Windows 側のファイルの扱いと権限が違うため） | 5 分 |
| Claude Code | ③以降だけ。Ubuntu の中に入れ、オーナー自身のアカウントでログインする（ログインの情報は報告に書かない） | 10 分 |
| Codex | ④以降だけ（第2の司法） | 10 分 |

①〜③で 1〜1.5 時間の見込み（実機で測っていない目安）。④⑤は前提が満たされてから見積もる。

## 2. 手順

### ① 閲覧と起動

```bash
cd ~ && git clone https://github.com/Isogyu/tsubuyaki-worklog.git && cd tsubuyaki-worklog
npm ci
npm run build
```

別の端末（Ubuntu のタブをもう1つ）で起動したままにする：

```bash
cd ~/tsubuyaki-worklog && npm run start -- -H 127.0.0.1 -p 3000
```

Windows のブラウザーで `http://localhost:3000/governance` を開く。確かめること：

- [ ] 統治シアターが出て、見ている記録が「提出記録」
- [ ] 再生で T-014 を押すと、図の光る場所が変わる
- [ ] 「はじめて見る」で5つの手順が進む

### ② 適合性テスト

```bash
node vgdd/conformance/run.mjs > /tmp/conf.txt; echo "exit=$?"; tail -3 /tmp/conf.txt
```

- [ ] `exit=` の値と、最後の行の合計（例：`414/414`）。落ちた判例があれば、判例の ID だけを書く

### ③ 保護の境界（AI は動かさない）

ここは手順を確定していない。オーナーの実機の時間が決まったら、立法補佐が macOS の配置（`.claude/settings.json` の sandbox の設定、`~/tsubuyaki-z3/` の場所）を WSL2 に合わせた確かめ方を書く。確かめたいことだけ先に挙げる：

- [ ] Claude Code の sandbox が WSL2 で有効になるか（`claude` の起動のときの表示、または設定の確かめ）
- [ ] sandbox の中の Bash から、作業フォルダの外に置いた合成の Z3 のファイルを読めない・書けないか
- [ ] フック（`vgdd/hooks/policy.mjs`）が動き、保護パスへの書き込みを拒むか

どれか1つでも成り立たなければ、④⑤は行わずに報告する。

**④⑤の前提（今は満たしていない）**：裁判所の監査は `vgdd/scripts/sandboxed-run.sh` で macOS の `sandbox-exec` を必須にしている。シェルにも BSD の書き方（`sed -i ''`・`df -g` など）が残っている。Linux（WSL2）で監査のコードを隔離する層と、シェルの互換の修正が入るまで、④⑤は予定に入れない。Claude Code の sandbox（③）と、裁判所の監査の sandbox は別のものとして確かめる
