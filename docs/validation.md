# 主張と証拠の対応（VGDD Governance Kernel、法律 p0.4.8）

作品で言うこと（主張）を、規範（仕様）・判例（適合性テスト）・実運用の記録に結ぶ。**確かめた範囲**の列は、どの方法で確かめたかを分けて書く。「実装済み」と書いてよいのは、判例か実運用の記録で確かめたものだけ（憲法の約束4）。規範の正本は `vgdd/kernel/SPEC.md` と `vgdd/kernel/capabilities.json`。ここは案内で、規範を写さない。

- 試験の対象：法律 p0.4.8（`vgdd/kernel/capabilities.json` の `kernel_version`）
- 適合性テスト：`node vgdd/conformance/run.mjs`（依存なし、Node 22 以上）。原本 414/414。稼働中の写し（`--impl z3`）は 2026-11-07 15:10 に 414/414（記録は Z3 にあり、公開の写しは `docs/governance/kernel-invariants.json` の `verified_by`）。p0.4.7 の時点は 410 件（11:08）、p0.4.5 の時点は 387 件（11/7 01:25 に稼働中の写しで 387/387）
- 実運用の記録：票の §6（`docs/tasks/T-0*.md`）、票の盤（`docs/tasks/_board.json`）、操作の集計（`docs/governance/summary.json`）。証拠ストアと判定の本文は Z3 にあり、公開しない

## 2. 正常な仕事の完了（例：T-022 Kernel の区画）

1. 行政の長の下書き（11/6 02:2x）→ 立法補佐が法律の書き出しの形に合わせ、Codex の点検（13 件）を反映して T-022 として main に固定
2. オーナーが approve-spec（06:19）→ Kernel の写しで承認済みを確認 → 行政の長が作業員 W18 を worktree で起動
3. 申請 → 裁判所が最新の main と組み合わせた候補を検査（監査・judge・Codex・Codex security すべて APPROVED）→ held（06:36）
4. 立法補佐が候補を動かし、本番の写しで画面を確認 → オーナーが release → main に統合（`status: merged`）

## 3. 状態の違いと、次に動く担当

| 状態 | 意味 | 次に動く担当 |
|---|---|---|
| 差し戻し（in_progress） | 監査か司法が不合格。上限3回 | 行政の長（作業員に直させて再申請） |
| 司法が使えない（申請が残る） | 判定が成り立たない。差し戻しではない。同じ申請で3回なら blocked | オーナー（司法の環境を確かめる） |
| 承認待ち（blocked、未承認） | 仕様の承認がない・承認の後に変わった | オーナー（approve-spec） |
| 分かれた（blocked） | judge と Codex が重大な指摘で分かれた | オーナー（裁定） |
| held | 夜間の合格。統合していない | オーナー（画面を見て release） |
| 停止中 | Kernel の STOP。停止の後に始まる操作を拒否 | オーナー（kernel-resume.sh で条件を確かめて再開） |
